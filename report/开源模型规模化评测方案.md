# CC-Eval 开源模型规模化评测方案（非 API 路线）

> 2026-09-06 · 目标：让 CC-Eval 能覆盖 HuggingFace / ModelScope 上的海量开源模型，而不逐家调 API

## 〇、为什么必须走非 API 路线

- API 只覆盖**厂商愿意开放**的少数模型（我们 v1.0 测了 11 个）；
- HuggingFace 上文本生成类模型已达百万量级（去重后基座+主流微调约数万），逐个 API 不可能；
- 开源权重模型可以**本地推理**，成本只是 GPU 电费，且结果完全可复现（固定权重、固定解码）。

## 一、三层技术路线（按成本从低到高）

### Tier 1：对数似然评测（loglikelihood，不生成文本）——可覆盖"百万级"

**原理**：把题目改写成选择式，分别计算模型给每个候选答案的 log 概率，取 argmax 作为模型答案。纯前向计算，无采样、无解码。

| CC-Eval 任务 | loglikelihood 化改造 |
|---|---|
| KNO 音节/汉字/词/语法定级 | 候选 "1"~"6"、"7-9" 七选一，比较 logprob |
| PHO 音节合法性 | 候选 "合法"/"非法" 二分类 |
| PHO 音节定级 | 同 KNO |
| PED 条文定位 | 候选条款编号多选一 |
| ERR 偏误类型 | 候选偏误类型标签多选一 |

**优势**：
- 每个模型只需前向推理，一张消费级 GPU 几分钟测完一个小模型；
- **规避了"指令遵循能力"混淆**——小模型/基座模型不会按 JSON 格式作答，但它们内部可能真的有知识，loglikelihood 直接读知识、不考格式；
- 完全确定性，无温度噪声。

**局限**：只能测判别式任务；GEN 限级改写、教学设计等生成式任务无法用此法。

**工程载体**：把 CC-Eval 包装成 [lm-evaluation-harness](https://github.com/EleutherAI/lm-evaluation-harness)（EleutherAI，社区事实标准）的一个 task——写若干 YAML 配置 + 少量 Python。之后任何人一条命令即可测任意 HF 模型：
```bash
lm_eval --model hf --model_args pretrained=Qwen/Qwen2.5-7B --tasks cceval_kno,cceval_pho
```
Open LLM Leaderboard 就是用这套管线跑全社区的，接入它等于获得"自动覆盖新模型"的能力。

### Tier 2：本地批量生成评测（vLLM / llama.cpp）——覆盖有生成能力的模型

- 用 **vLLM** 离线批推理：同一题库、同一 prompt，一次加载权重跑 1735 题，7B 模型约十分钟；
- 权重格式覆盖：HF Transformers 原生（vLLM）、GGUF 量化（llama.cpp，Mac/CPU 可跑）、AWQ/GPTQ；
- 我们的 runner 已是 OpenAI 兼容协议，vLLM 的 `vllm serve` 直接起本地兼容端点，**runner 零改动**，`--base http://127.0.0.1:8000/v1` 即可；
- GEN/SCO/CUL 等生成题沿用现有确定性评分器。

### Tier 3：API 评测（现有 v1.0 方法）——闭源商业模型

三层互补：Tier 1 做**广度普查**（所有开源模型），Tier 2 做**生成能力深测**（有足够能力的开源模型），Tier 3 做**商业模型**。

## 二、百万模型的现实过滤策略

HF 百万模型中绝大多数是重复微调/合并/废弃品，建议入测门槛：

1. pipeline_tag = text-generation 且参数量 ≥0.5B；
2. 下载量/点赞过阈值（社区信号）；
3. 去重：同一基座的微调按家族聚类，每族选代表；
4. 架构白名单：vLLM/lm-eval 支持的架构（Llama/Qwen/Mistral/GLM/Yi 等几十个）；
5. 中文相关性初筛：config 或模型卡含中文语料声明（可选，不强求——"英文模型中文教学能力"本身是有趣的对照组）。

实际入测量级：**数千个代表性模型**，Tier 1 每台 GPU 每天可测数百个，一两周即可出全榜。

## 三、对论文与项目的价值

1. **样本量跃升**：从 11 个商业模型到数千个开源模型，"能力—标准背离""限级生成失守"等结论可以在大样本上做**相关性检验**（参数量/训练数据/中文占比 vs CC-Eval 各维度得分），从"11 点描点"升级为"分布规律"；
2. **基座 vs 微调对照**：loglikelihood 法可测 base model（无指令微调），回答"标准知识是预训练带来的还是对齐带来的"；
3. **榜单效应**：接入 lm-eval-harness / Open LLM Leaderboard 生态，CC-Eval 才有机会成为社区持续使用的公共度量衡——这正是"标准需要足够多人用"的落地路径。
